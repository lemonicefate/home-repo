# Development workflow

## Define

- 先確認現況、目標、非目標及風險；只詢問會實質改變方案的問題。
- 優先研究既有專案、上游套件與可複用成果。MVP 應採最小可用方案。
- 需求有歧義時先釐清，再以 spec 與可驗收的垂直切片拆票。簡單任務不強制完整流程。

## Implement

- 讀取目標 Repo 的規則、工作樹狀態、相關程式及測試。
- TDD：先用公開介面描述預期行為，建立失敗測試，再實作最小改動、重跑並必要時重構。
- 每個切片保有可驗證結果。保留既有非相關程式碼與使用者改動。
- 在隔離環境使用合成資料；禁止為了測試通過而弱化安全檢查。

## Verify and deliver

- 記錄 commit、實際執行命令、通過/失敗/跳過數、未測部分及回復方式。
- 無法執行的測試標記 NOT VERIFIED；不把靜態檢查當作執行驗收。
- PR 只包含核准範圍的變更；說明目的、測試、相依性及部署風險。合併和部署依專案授權。
- 可重複使用且跨專案的決策，才回寫 Home Repo；即時狀態留在原 Issue/PR。
